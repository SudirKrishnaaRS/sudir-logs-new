## Mission

Become a confident Next.js developer: ready for a Next.js interview, and ready to open a production codebase at work and know what every file is doing. Done looks like being able to:

- Explain CSR, SSR, SSG and ISR, and say which one a page is using and why
- Say what runs on the server and what runs in the browser, and place `"use client"` correctly
- Build routes with the App Router: pages, layouts, dynamic segments, loading, error and 404 files
- Fetch data in Server Components and stream the slow parts, and know when to still fetch on the client
- Use the client-side tools every codebase has: navigation hooks, a providers wrapper, React Query
- Diagnose and fix a hydration error
- Write API endpoints with Route Handlers, and know when a Server Action is the better tool
- Mutate data with Server Actions, with validation, pending states and revalidation
- Debug "why is my page stale?" with a working model of caching
- Protect routes with Proxy and cookie sessions
- Recognise Pages Router code in an older codebase
- Build and deploy a full-stack app with Postgres

Out of scope for this track: deep Pages Router, automated testing, Docker and self-hosting, advanced routing (parallel and intercepting routes get a short "recognise it" note in Capstone 1).

<Callout type="react" title="The one question behind all of Next.js">

Next.js is React plus a server. Almost every new idea in this track is an answer to one question:
**"does this code run on the server, or in the browser?"** The two prerequisite lessons build that picture first.
After that, every feature is a variation on it.

</Callout>

## React → Next.js, concept for concept

| React (you know this) | Next.js equivalent (you're learning this) |
|---|---|
| `<Routes>` + `<Route path>` in React Router | Folders and a `page.tsx` inside `app/` |
| A shared layout component wrapping routes | `layout.tsx`: wraps every page below it |
| `useParams()` / `useSearchParams()` | The `params` / `searchParams` props |
| `useNavigate()` / `useLocation()` | `useRouter()` / `usePathname()` |
| Wrapping `<App />` in context providers | A `providers.tsx` Client Component inside the root layout |
| `useEffect` + `fetch` + a loading state | `async` Server Component + `loading.tsx` |
| Error Boundary | `error.tsx` |
| Every component you've written so far | A Client Component (`"use client"`) |
| `onSubmit` → `fetch('/api/...')` | A Server Action (`"use server"`) |
| An Express route (`app.get(...)`) | A Route Handler (`app/api/.../route.ts`) |
| Express middleware | `proxy.ts` (Next.js calls middleware "Proxy" since v16) |
| React Query cache invalidation | `revalidatePath()` / `revalidateTag()` |
