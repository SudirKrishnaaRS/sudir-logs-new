## Mission

Go from zero backend experience to confidently reading, writing, and debugging a production-grade Express + PostgreSQL API. Done looks like being able to:

- Explain the request/response lifecycle and where Express fits, without hand-waving
- Build a REST API from scratch: routing, middleware, params/query/body, centralized error handling
- Structure a project the way production codebases do (routes / controllers / models)
- Connect to PostgreSQL and do CRUD with parameterized queries
- Implement auth: bcrypt password hashing + JWT issuing and verification via middleware
- Validate requests and configure CORS so a React frontend can call the API
- Open an unfamiliar Express codebase and identify what each piece does on the first read

Out of scope for this track: MongoDB, full automated test suites, Docker / CI-CD / deployment.

<Callout type="react" title="Your anchor">
  Just like `components + props + state + hooks` is ~80% of daily React work, the path below
  is the ~80% of daily Express work. Master this and a production Express codebase stops looking like magic.
</Callout>

## React → Backend, concept for concept

| React (you know this) | Express equivalent (you're learning this) |
|---|---|
| Functional component | Route handler function `(req, res) => {}` |
| Props (data in) | `req.params` / `req.query` / `req.body` (data in) |
| Return value / JSX (output) | `res.json()` / `res.send()` (output) |
| Hooks (`useEffect` runs around render) | Middleware (`req, res, next` runs around the route) |
| React Router routes | Express routes (`app.get`, `app.post`...) |
| Component file structure | routes / controllers / models folder structure |
| Context / global state | `req.user` set by auth middleware |
| `fetch()` call you write in React | The API endpoint you're about to learn to build |
