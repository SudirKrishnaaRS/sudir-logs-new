## Dynamic segment patterns

| Pattern | Example request | req.params |
|---|---|---|
| `/todos/:id` | `/todos/7` | `{ id: '7' }` |
| `/users/:userId/todos/:todoId` | `/users/3/todos/9` | `{ userId: '3', todoId: '9' }` |
| `/todos/:id?` (optional) | `/todos` or `/todos/7` | `{}` or `{ id: '7' }` |
| `/files/*` (wildcard) | `/files/images/logo.png` | `{ 0: 'images/logo.png' }` |

<Callout type="info" title="Express 5 changed these two">
  The optional and wildcard rows above are Express 4 syntax. In Express 5, `?` is no longer supported, so write
  an optional segment in braces: `/todos{/:id}`. A wildcard must be named, as in `/files/*splat`, and
  `req.params.splat` is an array of segments (`['images', 'logo.png']`), not one string.
  Source: [Express 5 migration guide](https://expressjs.com/en/guide/migrating-5.html#path-syntax).
</Callout>

<Callout type="warn" title="Always remember">
  `req.params` and `req.query` values are always **strings**, even when they
  look numeric. Convert with `Number(...)` before comparing to a database ID.
</Callout>

<Callout type="warn" title="Route order">
  Express matches top to bottom and stops at the first match. Put specific paths (`/todos/new`)
  **above** dynamic ones (`/todos/:id`), or the dynamic route will swallow them.
</Callout>

## Sending a response

| Method | What it does |
|---|---|
| `res.json(data)` | Sends JSON - use this almost always |
| `res.send(data)` | Sends a string, Buffer, or object |
| `res.status(code)` | Sets the status code, chain before `.json()` |
| `res.end()` | Ends the response with no body |
