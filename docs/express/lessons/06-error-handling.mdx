<Callout type="react" title="Start from what you know">
  You've used a React `<ErrorBoundary>` - one component that catches errors thrown anywhere
  below it in the tree, so every child doesn't need its own try/catch. Express has the exact same idea:
  one piece of middleware that catches errors from anywhere in your API.
</Callout>

## The signal: four parameters, not fewer

Express doesn't use a special name to recognize error-handling middleware - it counts **function arity**.
Exactly four parameters, in this order, and Express treats it differently from every other middleware:

```js title="index.js"
app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({ error: 'Something went wrong' });
});
```

<Callout type="warn" title="Must go last">
  This has to be the **very last** `app.use()` in your file - after every route. Express
  walks middleware top to bottom, same rule as Lessons 02 and 03.
</Callout>

## Getting an error there: next(err)

Throwing inside an async route handler doesn't automatically reach your error middleware - you catch it
yourself, then hand it off:

```js
async function getTodoById(req, res, next) {
  try {
    const todo = todoModel.getById(req.params.id);
    if (!todo) return res.status(404).json({ error: 'Todo not found' });
    res.json(todo);
  } catch (err) {
    next(err); // skip everything else, jump straight to the error handler
  }
}
```

`next()` with nothing means "continue normally." `next(err)` with an error means
"abandon the normal chain, go straight to whatever has four parameters."

The happy path:

The error path - it jumps, it doesn't continue:

<Flow label="Error path: the handler calls next(err) and control jumps to the error middleware">
  <Step type="client">Request</Step>
  <Step>middleware</Step>
  <Step type="warn">handler throws, calls next(err)</Step>
  <Step type="error">error middleware (4 args)</Step>
</Flow>

## The other gap: routes that don't exist at all

None of the above fires if the URL simply matches **no route** - Express just sends a plain-text
"Cannot GET /whatever" by default. Add a catch-all right before your error handler:

```js title="index.js"
// after every real route, before the error handler:
app.use((req, res) => {
  res.status(404).json({ error: 'Route not found' });
});

app.use((err, req, res, next) => {
  console.error(err.stack);
  res.status(500).json({ error: 'Something went wrong' });
});
```

## Full ordering, in one file

| Order | What |
|---|---|
| 1 | Regular middleware (logger, `express.json()`) |
| 2 | Your real routes (`app.use('/todos', todoRoutes)`) |
| 3 | Catch-all 404 (no route matched) |
| 4 | Error-handling middleware, 4 args - always last |

## Try it yourself (10 min)

Add the catch-all 404 and error handler above to the bottom of your `index.js`. Then test both gaps:

```bash title="terminal"
curl http://localhost:3000/nonexistent
# {"error":"Route not found"}
```

## Interview angle

<details>
  <summary>How does Express know a middleware is an error handler?</summary>

  By its arity: a function declared with exactly four parameters `(err, req, res, next)` is treated as
  error-handling middleware. Express skips it during normal flow and only calls it once an error has been
  passed along with `next(err)` (or thrown synchronously inside a handler). Dropping the unused `next`
  parameter silently turns it back into regular middleware.
</details>

<details>
  <summary>What's the difference between a 404 handler and an error handler?</summary>

  A 404 is not an error in Express's eyes - it just means no route matched, so the request falls off the
  end of the chain. You handle it with a normal `(req, res)` middleware registered after every route. The
  four-argument error handler goes after that, and catches anything passed to `next(err)`.
</details>

<details>
  <summary>Why wrap async handlers in try/catch and call `next(err)`?</summary>

  In Express 4, a rejected promise inside an async handler is not seen by Express, so the error never
  reaches your error middleware and the request can hang. Catching it and calling `next(err)` hands it off
  explicitly. Express 5 forwards rejected promises from handlers to the error middleware automatically.
</details>

## Key terms

<Terms>
  <Term name="Error-handling middleware">A middleware with four parameters `(err, req, res, next)`, registered last, that turns errors into responses.</Term>
  <Term name={<code>next(err)</code>}>Skips the rest of the normal chain and jumps straight to the error-handling middleware.</Term>
  <Term name="Function arity">The number of declared parameters a function has - how Express tells error middleware apart.</Term>
  <Term name="Catch-all 404">A `(req, res)` middleware after every route that answers requests no route matched.</Term>
</Terms>
