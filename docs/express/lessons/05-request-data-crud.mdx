## req.body - what it is, and what it isn't

`req.body` holds whatever JSON the client sent in the request body. It only exists because of
`app.use(express.json())` from Lesson 03 - the middleware that parses the raw request into that object
before your controller ever sees it.

```js
// Client sends: POST /todos  { "title": "Buy milk" }
function createTodo(req, res) {
  console.log(req.body); // { title: 'Buy milk' }
}
```

<Callout type="warn" title="Never trust the body">
  A client can send anything - or nothing. Before using `req.body.title`, check it actually exists.
  Skipping this is the #1 source of confusing 500 errors in beginner APIs.
</Callout>

```js
function createTodo(req, res) {
  const { title } = req.body;

  if (!title) {
    return res.status(400).json({ error: 'title is required' }); // stop here - bad request
  }

  const newTodo = todoModel.create({ title });
  res.status(201).json(newTodo);
}
```

<Note>
  This is manual validation - fine for now. Lesson 13 replaces it with `express-validator`, a library built for exactly this, once your rules get more complex.
</Note>

## Completing the model

Add `update` and `remove` to `models/todoModel.js`, alongside what Lesson 04 already has:

```js title="models/todoModel.js"
update: (id, data) => {
  const todo = todos.find(t => t.id === Number(id));
  if (!todo) return null;
  todo.title = data.title;
  return todo;
},

remove: (id) => {
  const index = todos.findIndex(t => t.id === Number(id));
  if (index === -1) return false;
  todos.splice(index, 1);
  return true;
},
```

## Completing the controller

```js title="controllers/todoController.js"
function updateTodo(req, res) {
  const { title } = req.body;
  if (!title) return res.status(400).json({ error: 'title is required' });

  const updated = todoModel.update(req.params.id, { title });
  if (!updated) return res.status(404).json({ error: 'Todo not found' });

  res.json(updated);
}

function deleteTodo(req, res) {
  const deleted = todoModel.remove(req.params.id);
  if (!deleted) return res.status(404).json({ error: 'Todo not found' });

  res.status(204).end(); // success, nothing to send back
}

module.exports = { getAllTodos, getTodoById, createTodo, updateTodo, deleteTodo };
```

## Completing the routes

```js title="routes/todos.js"
router.put('/:id', todoController.updateTodo);
router.delete('/:id', todoController.deleteTodo);
```

Your Todo API now supports all four operations, split cleanly across the three layers from Lesson 04.

## Try it yourself (10 min)

Run through the full lifecycle of one todo:

```bash title="terminal"
curl -X POST http://localhost:3000/todos -H "Content-Type: application/json" -d '{"title":"Buy milk"}'
curl http://localhost:3000/todos/2
curl -X PUT http://localhost:3000/todos/2 -H "Content-Type: application/json" -d '{"title":"Buy oat milk"}'
curl -X DELETE http://localhost:3000/todos/2
curl http://localhost:3000/todos/2
```

</Callout>

## Interview angle

<details>
  <summary>Where does `req.body` come from?</summary>

  Express does not parse request bodies on its own. Body-parsing middleware such as `express.json()`
  reads the raw request, parses the JSON, and puts the result on `req.body` before your handler runs.
  Without it, `req.body` is `undefined` no matter what the client sent.
</details>

<details>
  <summary>Why validate `req.body` in the handler, and what should a failed check return?</summary>

  The client controls the body and can send anything, including nothing. Checking required fields up
  front lets you return a clear `400 Bad Request` and stop, instead of letting missing data cause a
  confusing `500` deeper in your code or quietly saving a bad record.
</details>

<details>
  <summary>Which status codes fit update and delete, including the not-found case?</summary>

  A successful update returns `200` with the updated record; a successful delete with nothing to send
  back returns `204 No Content`. If the id in the URL doesn't match any record, both should return
  `404 Not Found`.
</details>

## Key terms

<Terms>
  <Term name="CRUD">Create, Read, Update, Delete - mapped to POST, GET, PUT and DELETE.</Term>
  <Term name={<code>req.body</code>}>The parsed request body the client sent; populated by `express.json()`.</Term>
  <Term name="Manual validation">Checking required fields yourself and returning `400` early when they're missing.</Term>
  <Term name={<code>res.status(204).end()</code>}>Ends a successful response with no body, as used for delete.</Term>
</Terms>
