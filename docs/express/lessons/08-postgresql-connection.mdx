## Install what you need

```bash title="terminal"
npm install pg dotenv
```

`pg` (node-postgres) talks to PostgreSQL. `dotenv` loads secrets from a file instead of hardcoding them.

## Never hardcode credentials

Create a `.env` file in your project root:

```bash title=".env"
DATABASE_URL=postgres://postgres:yourpassword@localhost:5432/tododb
```

<Callout type="warn" title="Add it to .gitignore immediately">
  A `.env` file holds real secrets. Commit a `.gitignore` with `.env` in it
  *before* your first commit - once a secret is pushed to a public repo, it's compromised even if you delete it later.
</Callout>

<Callout type="react" title="React analogy">
  This is the same idea as `.env` files in Vite/Create React App (`import.meta.env` /
  `process.env.REACT_APP_...`) - keep config out of your source code so it can differ per environment
  (your laptop vs. production) without touching a single line of code.
</Callout>

## Loading it: dotenv

At the very top of `index.js`, before anything else runs:

```js title="index.js"
require('dotenv').config();
```

Now `process.env.DATABASE_URL` holds the string from your `.env` file, anywhere in your app.

## The connection pool

Create `db/pool.js` - one shared pool the whole app reuses:

```js title="db/pool.js"
const { Pool } = require('pg');

const pool = new Pool({
  connectionString: process.env.DATABASE_URL,
});

module.exports = pool;
```

<Callout type="react" title="Why a pool, not one connection">
  Remember Lesson 00: one thread handles many requests by handing off slow work. A **pool** keeps
  several database connections ready so multiple requests' queries can be in flight via libuv at once, instead
  of queuing behind a single connection.
</Callout>

## Creating the table

Run this once, via `psql` or any Postgres GUI:

```sql
CREATE TABLE todos (
  id SERIAL PRIMARY KEY,
  title TEXT NOT NULL,
  completed BOOLEAN DEFAULT false
);
```

## Your first real query

```js
const pool = require('./db/pool');

pool.query('SELECT * FROM todos').then((result) => {
  console.log(result.rows); // an array of real rows from Postgres
});
```

`pool.query()` returns a **Promise** - it's async, handed off to libuv exactly like the
`setTimeout` in Lesson 00. Your code doesn't block waiting for the database to respond.

## Interview angle

<details>
  <summary>What's the difference between a `Pool` and a `Client` in node-postgres?</summary>

  A `Client` is a single connection to Postgres. A `Pool` manages several clients and hands them out as
  needed: `pool.query()` checks a client out, runs the query and returns it to the pool automatically.
  For work that must run on one connection, like a transaction, you check a client out with
  `pool.connect()` and must call `client.release()` when you're done.
</details>

<details>
  <summary>Why create the pool once in its own module instead of inside each request?</summary>

  Opening a database connection is slow, and a pool is meant to be long-lived so its connections get
  reused across requests. Node caches modules after the first `require()`, so every file that requires
  `db/pool.js` gets the same pool instance.
</details>

<details>
  <summary>Why must `require('dotenv').config()` run before anything else?</summary>

  It copies the values from `.env` into `process.env`. Any module that reads `process.env.DATABASE_URL`
  while it loads - such as `db/pool.js` creating the pool - would see `undefined` if dotenv hadn't run yet.
</details>

## Key terms

<Terms>
  <Term name={<code>pg</code>}>node-postgres, the library that lets Node talk to PostgreSQL.</Term>
  <Term name={<code>.env</code>}>A file of environment variables (like `DATABASE_URL`) kept out of source control.</Term>
  <Term name={<code>process.env</code>}>The object holding environment variables at runtime; dotenv fills it from `.env`.</Term>
  <Term name="Connection pool">A set of reusable database connections shared by the whole app.</Term>
  <Term name={<code>pool.query()</code>}>Runs one SQL query on a pooled connection and returns a Promise of the result.</Term>
</Terms>
