## Full 2-week syllabus (roadmap)
This is the working plan - also rendered on the track overview page `docs/express/index.mdx`. Adjust pacing/order based on actual progress and learning-records, don't treat this as fixed.

**Week 1 - Get a REST API running (in-memory, no DB yet)**
1. What is a backend? Request/response cycle, where Express fits vs. `fetch()` calls they already write in React. Hello-world server.
2. Routing - `app.get/post/put/delete`, route params vs. query params.
3. Middleware - the `(req, res, next)` model, `app.use`, ordering. The single biggest "aha" of Express.
4. Project structure - routes/controllers/models separation (the Express equivalent of component file structure).
5. Request data - `req.body`, `express.json()`, building full CRUD against an in-memory array.
6. Error handling - try/catch in async routes, centralized error middleware, correct HTTP status codes.
7. Capstone/review - build a small Todo API end-to-end tying days 1-6 together, no new concepts.

**Week 2 - Real backend concerns (Postgres, auth, production hygiene)**
8. PostgreSQL + Express - `pg` connection pool, `.env` config, first real query.
9. CRUD against Postgres - parameterized queries, SQL injection awareness.
10. ORM option - brief Prisma intro as an alternative to raw SQL (confirm interest before going deep).
11. Authentication part 1 - password hashing with bcrypt, issuing a JWT on login.
12. Authentication part 2 - auth middleware, verifying JWT, protecting routes, `req.user` pattern.
13. Validation + CORS - `express-validator` for input validation, `cors` middleware so the React frontend can call the API cross-origin.
14. Capstone - full CRUD + auth + Postgres API a real React app could consume, plus a short "what's next" pointer (testing, Docker, deployment) as out-of-scope teasers only.
